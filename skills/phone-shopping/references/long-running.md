# 长任务留档、进度与设备暂离

适用于多品类采购、跨平台研究、可能中断/跨天继续的真机任务。目标是下一次执行者只读持久记录即可继续，而无需重问需求、重复浏览或重复副作用。以下是工作记录，不记录模型内部推理过程、无关聊天、地址、账号、认证及支付资料。

## 持久化最小结构

选一个任务目录，使用现有可靠记录系统或以下文件结构，路径写入用户可见任务文档：

- `requirements.json`：稳定需求ID、系统/用途、数量、硬约束、状态、关联候选；改变需求时保留旧值和用户修正来源。
- `candidates.json`：每个平台/店铺/SPU/SKU分别一条，稳定ID、商品编号/链接（无则unknown）、选中配置/数量；价格原标签/金额/优惠条件及是否已领取、商详价/车价/成交价分开；观察时间；核心参数及逐字段来源；图片/正文读取覆盖与未读断点；缺失/冲突；推荐/淘汰/待决策理由、同款匹配依据/替代关系；加购与分组实际状态。
- `customer-queries.json`：原店铺/商品/SKU、一次发送的问题原文（历史无原文只写摘要）、发送时间和核验、机器人/人工/图片回复及必要参数、证据和待答缺口。未读不等于没发，已读不等于回答；未知结果先查原会话。
- `events.jsonl`：带事件ID/时区时间、设备/平台、候选ID、动作/操作ID、目标与预期、结果/不确定性、证据引用和断点增量的追加日志。记录搜索/进入/规格/核心图序号、客服、加购、分组、重要取舍、异常和恢复；低价值导航可合并为一个短路径，但保留批次完成与停止位置。不覆盖旧事件；错误判断用纠正事件保留来龙去脉。
- `checkpoint.json`：约束与授权范围、最新有效进度及统计分母、各设备ready/暂离/认证状态和检查时间、实际App/页/SKU/图片序号、每设备下一步、未决副作用、原购物车基线/本次已核条目、已发问题、待回复/待决策清单、定时汇报ID、外部文档引用和最后同步状态。
- `evidence/`：支持决定性结论的相关原生观察、必要参数/客服/购物车局部截图、说明书/官方链接和访问时间。裁掉无关通知、地址/身份/支付信息。工具store只用于临时编排；图片路径易被覆盖时及时另存。历史没保存的截图明确缺口，不回填成原始证据。

字段可按任务简化，但不能丢失SKU关联、来源/时间、关键判断依据和结果未知的副作用。文件用临时文件+原子替换写快照；事件先追加并flush，再更新断点。`scripts/record_event.py --root TASK_DIR PAYLOAD.json`可记录`event`与顶层`checkpoint_patch`；事件ID供本地重复写去重，日志先于断点时可重放增量修复。该脚本不操作手机，也不把事件ID当平台加购幂等保障。业务动作前先持久化意图；落盘失败则先修复记录，再执行会改变外部状态的动作。

当前记录脚本对对象字段递归合并、数组和标量整体替换；更新某设备单一字段不能抹掉另一设备断点，更新一个系统组不能抹掉其他组。新事件标记`recursive_v1`语义，重放旧事件保留原顶层替换语义；迁移已有台账时先核对真实记录补齐曾遗漏字段。数组需传完整预期内容，明确清空使用空数组。

## 副作用与恢复顺序

1. 操作前记录目标账号/平台、店铺、SKU/数量或组名、操作ID，状态`intent`；检查该目标此前是否已存在/已发送。
2. 执行一次，保存工具返回的实际错误、`action_executed`/`uncertain`/batch完成位置；状态`executed_unverified`或`unknown`，不能把accepted当业务完成。
3. 下一次相关观察核对具体条目/发送气泡/组归属，写`confirmed`；发现未生效写`not_applied`。只有新证据明确没发生，才继续余下步骤。
4. 断联/进程中断后先读journal和checkpoint，检查未决操作，再取ready和实际页面；即使旧页消失也通过商品ID/型号/店铺重新定位。禁止重放整批、用购物车角标推测数量、重发所有待答问题。

## 动态多设备分工

维护共享候选队列与每设备当前工作项、App/账号可用性、页面断点、未决副作用和占用状态。可并行处理不同品类/候选、同款不同平台报价、推荐信息调研或客服回查；不把某台手机长期固定为某电商平台。根据已登录 App、当前页面、预计切换成本、等待回复和临时断联动态调整，任务转移前保存断点，接手设备先核对真实页面和已有结果。

同一部手机始终由一个执行者串行控制；跨设备仅在宿主/工具确实支持独立绑定时并行。PUA 单例服务只绑定一台设备时，不并发 configure 切走别人的目标；需要独立会话/实例，若 provider 不支持就串行使用该能力，或让另一 provider 承接另一设备。不要把任务队列并列写成真实并行已验收。需要代理委派时遵守当前宿主和用户授权，不自动创建新的用户聊天。

跨设备去重按平台账号、店铺、商品与 SKU/数量核对；只读调研可以重复取最新价，客服、加购和分组采用共享未决操作表。账号与优惠不同则分别记录，不能用设备切换后更低的报价直接承诺原账号可得。

## 单台与全部暂离

每台设备独立保存断点和工作队列；同一部手机由一个执行者串行操作。用户拿走设备时停止对它的动作/截图，标记`temporarily_unavailable`与最后已确认结果，不持续诊断或要求立刻归还。另一台仍ready则继续其平台可独立调研、客服回查及已授权加购，价格/账号差异保留。跨设备同款已加过先核对，避免重复。

所有设备不可用时，保存`waiting_for_devices`、未决操作和可立即恢复的下一步，继续已有证据整理/比价/文档同步。没有可做的离线工作时等用户恢复或已授权的宿主检查；没有常驻能力不能宣称仍在后台运行。暂离是可恢复等待，不是采购任务完成/取消；有goal工具时遵守其状态规则，不为一次断联擅自标永久blocked。

重连用现有插件状态/活动恢复job和ready，只做有界通道恢复；不整套重装，不切未授权账号，不绕过锁屏/认证。用户明确拿走设备或反复无连接时，保存状态并停止恢复循环。恢复后核对前台/账号/待决操作，检查报价和配送时效；历史参数可沿用对应型号证据，漂移字段重新取，不从头遍历已排除候选。

## 进度与定时汇报

用户要求定时汇报时，记录间隔及最后报告时间；未给间隔可用15分钟。报告简短写总体估计、分母/依据、这段新增成果、待决策或缺口及下一步。分别统计已深入调研、已形成可购买推荐/有依据延期、已加购、尚未调研；候选数量、点击次数和加购件数不是完成率。有依据地调整进度，保留依据，不线性从耗时推算100%。

优先复用当前任务既有heartbeat，回读持久状态和下一次时间（宿主若不返回就注明不能确认）。汇报回调只读记录，不与活跃主任务争用手机；记录主执行最近活动/写入位置。断联无变化时避免重复告警，用户指定固定汇报则遵从；设备重新可用/新增关键结论及时报告。明确完成并最终交付后暂停该定时机制，保留审计与断点归档。

用户文档留当前结论和简短审计入口，详细事件放独立日志/子页；使用外部文档时先读目标文档，增量写并回读，保留用户原有内容。上下文压缩或结束前更新断点、未决操作和文档同步缺口；任何下一轮先读这些记录再执行。

## 跨设备接续时的消息刷新

同一平台另一设备首次打开可能仍显示旧会话列表或旧购物车角标。用该App当前可见的刷新方式做一次刷新，再进入原店会话核对原问题完整气泡、发送/已读标记和回复；未出现不等于从未发送，不可因此重发。确认相同会话可接续后，记录原发送设备与当前读取设备；购物车仍需独立核对实际SKU/数量/分组，不能由消息同步推定购物车已验收。

同一设备加购或分组后重新打开也可能短暂显示缓存条目、旧角标/组数量和加载动画。先做只读新观察，等实际列表更新，再核目标SKU数量与组归属；缓存首帧不作丢单/丢组证据，不能据此重复加购或修改分组。分组编辑卡片可能显示原价，购物车当前报价另记。

外部文档连接暂时失败时，本地追加日志和原子台账继续保存，记待同步项目。恢复后先读取目标页面和真实记录，用增量、唯一锚点编辑并回读；未知写入结果先查真实页面，不盲重放。把已验证的单设备切换与尚未验证的全设备恢复/宿主关闭能力分别记在验证范围。

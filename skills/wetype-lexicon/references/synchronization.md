# 同步与恢复流程

`wetype-sync` 支持有效词表写入正式个人学习词库。原生 Add 会生成学习记录和连续的新 action 序号，由恢复运行后的官方输入法沿原同步链路处理。正式3词已完成 iPhone、另一台 Mac 的0/3→3/3观察；未区分该次由增量动作还是整库快照完成传输。

## 分批准入

每个任务先全量规范化和文件内查重，再按连续行范围处理，每段最多500个去重词对。提交前从当前一致副本重新查重，既有词不调用 Add、不加频。沙箱worker沿普通全局配置装配真实KV编码，仅在目标词典实例的一次Add与任务等待期间暂控已恢复语义的运行字段，抑制附带旧词清理；恢复后再查词并导出记录。它依赖已验证内部布局，没有伪称官方公开bulk接口，也不修改正式App的配置。实际新增数决定动作数；任一新进程召回或完整 KV 审核失败时，该待提交副本不进入正式库。

检查 !dcact! 动作头、物理最大序号、!dcsc!CurrentInfoV3 本地消费水位、epoch及历史观察。积压加本次实际新增不得超过900；这是低于原消费者1000条裁剪阈值的保守本地窗口。缺口、序号回退、头落后、未知队列或身份变化拒绝继续，不修头、不剪 action、不伪造消费水位。

`waiting_sync` 保留词表与已提交游标，每段结束恢复官方服务，供消费者自然工作。`resume` 重新读当前状态，有余量才继续；可指定0–900秒的有界等待，默认立即返回，不创建后台自动续导。整个任务不承诺单次原子提交；中途等待或失败，之前已提交的批次保留。

本地水位可能因消费者裁剪路径前移，不能单独充当服务器 ACK。`completed` 只表示本地任务全部处理；云端到达和接收端候选要另行核对。

## 服务互锁

此版本的原生 LevelDB 锁不能与外部 POSIX 锁组成可靠互斥，官方输入法也可能自动重启。新入口核对唯一官方 launchd 服务及可执行文件后，暂时限制该服务启动，切ABC并正常退出输入法。服务退出后可从列表注销；任何新实例标签、实际进程或源文件变化都使提交失败。

服务互锁覆盖一个完整操作段，独立 guardian 通过专用管道和最长900秒期限监护。提交前重新检查 guardian、剩余期限、启动限制、实例列表、源词库完整清单和无进程状态。原子交换只发布审核过的前向状态。

正常释放后 guardian 恢复启动许可及原输入意图；异常 EOF 或超时先终止它自己的协调父进程并确认退出，再恢复输入服务，避免协调器在限制解除后继续交换。它不会强杀微信输入法。独立恢复进程、日志均位于私有工作区，不安装持久 LaunchAgent。

机器断电或重启可能保留 launchd 的禁用覆盖；`wetype-sync ... recover-service` 在版本检查及原生编译之前可用，依签名恢复日志恢复启动许可和输入状态。恢复会核对启动会话与进程出生时间，拒绝与存活的协调器或 guardian 竞争。缺失或损坏日志需保留现状诊断，不能据此随意启用别的服务。

## 事务与备份

实际新增批次先保留完整备份，再写前向事务日志；任务中记录批次计划、行范围、预期新增及事务绑定。崩溃后先用已保存的主记录摘要、队列与序号分类；已提交的批次推进游标，不重复 Add。未知状态保留当前库和所有副本，停止覆盖。

在交换前失败的批次不修改正式库；交换后的异常保留新状态并进入恢复分类，不自动交换旧快照。跨设备同步已运行后，恢复旧目录会重复使用动作序号，因此正式整库快照回滚不开放。纯撤销和官方“删除该词”是不同功能；后者还新增 kind150 屏蔽记录，本版本不自动执行它们。

## 验证

纯逻辑测试、真实原生隔离批量、模拟消费水位的续导、正式零新增流程，以及历史跨端到达分别记账。测试工具中的 mock 水位仅用于实验准入，不写真实 head、不裁动作，也不属于生产恢复方法。结果见 [验证记录](validation.md)。
